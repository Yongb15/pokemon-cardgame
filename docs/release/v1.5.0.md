## 1. 운영 DB (main 병합 전 — 순서 중요)
새 API는 시작할 때 0014~0018의 권한이 없으면 **시작을 거부**하므로 반드시 먼저 적용한다. 옛 API·웹은 새 테이블을 모르므로 영향 없음.
1. 복구 지점: Neon `production`을 부모로 브랜치 `pre-v1.5.0`(확인 뒤 삭제)
2. 마이그레이션 0014~0018: owner URL은 neonctl로 받아 변수에만 → `DATABASE_URL_OWNER="$OWN" npm run db:migrate`
3. 확인(불리언만, owner로 `has_table_privilege`/`has_column_privilege` 조회 — `scripts/db-check-api-role.ts`는 dev 전용이라 쓰지 않음. 최종 확인은 새 API의 시작 시 권한 검사):
   - POINTS·PACKS·AUCTIONS·NOTIFICATIONS 필요 권한 모두 true
   - 금지 권한 false: point_entries UPDATE/DELETE, auctions DELETE·seller_id/card_id/start_price UPDATE, bids UPDATE/DELETE, notifications DELETE·user_id/kind/auction_id UPDATE
   - `app_rw`·`collector_rw`는 account 스키마 접근 불가
4. 운영엔 `dev_marker`가 없음을 확인(테스트 로그인·테스트 경로가 켜질 수 없음)

## 2. 배포
1. `package.json` 1.5.0 커밋(develop) → develop → main PR → CI `check` → merge commit → 태그 `v1.5.0` → GitHub Release
2. Deploy API 워크플로가 `api`에 main 이미지 배포 → 시작 로그: 권한 검사 통과, "grants wider than needed" 없음, `auction sweep failed` 없음
3. Vercel production 배포 확인(정식 주소 번들 해시)

## 3. 출시 뒤 확인
- 정식 주소에서 로그인 → 보너스 10,000P 한 번, 출석, 카드팩 열기, 경매 목록(빈 상태), 알림 종
- Security: A-3 게이트(다른 사용자에게 닉네임이 보이는 곳 없음), 정식 번들에서 `/api/v1/test` 문자열 0건, 운영 `POST /api/v1/test/*` 404
- qa: 정식 주소 회귀(카드·시세·덱·로그인) + M7 화면 훑기. 운영에는 테스트 계정·짧은 경매(2m/5m)가 없으므로 실제 계정으로 1시간 경매 1건까지만

**롤백**: 웹은 Vercel 이전 배포로 promote, API는 `gcloud run services update-traffic api --to-revisions=<이전 리비전>=100 --region asia-southeast3`. 0014~0018은 테이블·권한 추가뿐이라 옛 코드와 호환. 포인트·경매 데이터는 남겨 둔다(다시 출시할 때 이어서 사용).
