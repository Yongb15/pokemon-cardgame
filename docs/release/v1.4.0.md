## 1. 운영 DB (웹 배포 전 — 순서 중요)
새 웹 코드는 `psa_price`를 읽는다: 테이블이 없으면 상세 시세 API 전체가 500이 되므로 **main 병합 전에** 적용.
1. 복구 지점: Neon `production`을 부모로 브랜치 `pre-v1.4.0`(확인 뒤 삭제)
2. 마이그레이션 0013: owner URL은 neonctl로 받아 변수에만 → `DATABASE_URL_OWNER="$OWN" npm run db:migrate`
3. 확인(불리언만): `collector_rw` psa_price·psa_refresh SELECT/INSERT/UPDATE true, DELETE/TRUNCATE false · `app_rw` psa_price SELECT true, INSERT/UPDATE false, psa_refresh 접근 false
4. 정식 `/api/cards/<id>/prices` 200(옛 코드는 새 테이블을 모르므로 영향 없음)

## 2. 수집기 (Cloud Run Job `price-collector`)
1. 새 이미지 빌드(`infra/collector/README.md` 절차, 업로드 목록 `.env` 0개) → digest로 Job 갱신
2. 비밀 연결: `gcloud run jobs update price-collector --update-secrets PRICETRACKER_API_KEY=pricetracker-api-key:1`
3. `collector-run` 계정에 `pricetracker-api-key` secretAccessor만 추가
4. 시험 실행: `COLLECT_LIMIT=1 PSA_LIMIT=3`으로 1회 → 로그 `psa: targets 3, saved …` 확인(크레딧 6)
5. 다음 예약 실행(19:30 UTC) 뒤 로그의 `psa:` 줄과 Pokemon Price Tracker 사용량 확인

1. `package.json` 1.4.0 커밋(develop) → develop → main PR → CI `check` → merge commit → 태그 `v1.4.0` → GitHub Release
2. Vercel production 배포 확인, 정식 주소에서 PSA 블록·시세 탭 PSA 10 보기
