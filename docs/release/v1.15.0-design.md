# v1.15.0 설계 — 시세 7일 순위 · 진화 링크 · 덱 예상 비용 · 세트 수집 현황

사용자 결정(2026-10-21): 아래 네 가지를 v1.15.0으로 묶어 낸다. 다음 v1.16.0(E2E 테스트·설계 문서)으로 포켓몬 프로젝트의 큰 기능을 마무리한다.

## 1. 시세 7일 상승·하락 순위 (`/prices`)
전체 카드 시세 수집은 10/10에 시작했다(10/21 기준 11일치). 7일 비교에 충분하다.

- **화면**: 시세 탭의 판 선택에 **[7일 상승] [7일 하락]**을 추가한다. 주소는 `/prices?edition=up|down`이고, 세트 선택(`&set=`)도 그대로 쓴다.
  - 행 구성: 카드, 지금 시세(원), **변화율(▲ +38.2% / ▼ −21.0%)**, 7일 전 시세(원)
  - 안내: "영문판 TCGplayer 기준이고, 7일 전과 같은 판본을 원래 통화로 비교해요(환율 변동 제외)."
- **API**: 기존 `GET /api/prices/top`에 `edition=up|down`을 더한다. 새 함수나 rewrite는 만들지 않는다.
  - 매개변수 규칙은 그대로다(edition·set만, 반복·빈 값은 400). 캐시는 1시간 엣지 + 10분 인스턴스 메모다.
- **계산**(`server/prices/top.ts`의 `rankMovers`)
  - 지금: 카드마다 지금 순위와 같은 방식으로 대표 시세를 고른다(TCGplayer 우선 → 판본 순서). 7일 안에 확인된 값만 쓴다.
  - 7일 전: **같은 출처·판본**에서 `captured_on ≤ 오늘−7`인 마지막 행을 쓴다. 표시 안 된(flagged=false) 값이어야 하고, 그 값이 `last_seen_on ≥ 오늘−14`일 때만 쓴다.
  - 변화율 = (지금 − 7일 전) / 7일 전. 금액은 원래 통화(USD 등)로 비교한다.
  - 잡음 제외: 두 값 모두 원화로 **₩3,000 이상**이고 변화율이 **5% 이상**이어야 한다. 기본 에너지와 PSA는 제외한다.
  - 30장까지 보여 준다. 정렬은 변화율, 같으면 지금 가격이 높은 순, 같으면 카드 id 순이다.
- **저장소**: `getLevelsAsOf(edition, day, sinceDay)`는 읽기 전용 쿼리 하나다(`app_rw` 권한 변경 없음). 응답에는 카드 id와 금액만 담는다.
- **P-1**: 시세 API는 공개 API로 안내하지 않는다(llms.txt·README API 문서에 넣지 않음).

## 2. 진화 링크 검색 정확도
- 문제: 카드 상세의 "← 리자드에서 진화"는 `/?q=리자드`라서 **부분 일치** 결과(예: 일레도리자드)가 섞여 나온다.
- 수정: 이름 검색(`in=name`)에서 **이름이 정확히 같은 카드를 앞으로** 옮긴다(정규화한 nameKo 또는 name이 검색어와 같은 경우). 각 묶음 안의 순서는 원래 정렬을 따른다.
- 진화 링크만이 아니라 모든 이름 검색이 같은 이점을 얻는다("피카츄" 검색 → 피카츄가 먼저). 응답 형식과 매개변수는 바뀌지 않는다.

## 3. 덱 예상 비용
- 덱 편집 화면과 공유 덱 화면, 덱 구성 아래에 표시한다.
  - "참고 시세 합계 **₩182,400** (시세 있는 카드 52/60장)"
  - 비싼 카드 TOP 5(카드 · 장수 × 1장 시세)
  - 안내: "영문판 TCGplayer 시세를 원화로 바꾼 참고값이에요. 포인트와는 관계없어요. 기본 에너지는 빼고 셌어요."
- 데이터: 기존 `GET /api/prices/batch?ids=`를 쓴다(정렬·중복 없음·50개씩 나눠 요청, 서버는 카드별 10분 메모 PA-1).
  - 카드 데이터에 없는 id와 기본 에너지는 보내지 않는다(400 방지).
  - 덱이 바뀌면 다시 요청하되, 이미 받은 카드는 브라우저가 기억한다.
- 개인정보 없음: 카드 id만 보낸다. 같은 덱 목록은 공유 링크에 이미 공개돼 있다.

## 4. 세트 수집 현황 (컬렉션 화면)
- 지금 있는 세트별 막대(모은 수/전체)에 다음을 더한다.
  - **퍼센트**를 붙인다.
  - 다 모은 세트에는 **"완성" 표시**를 단다.
  - 세트 줄을 누르면 **"아직 못 모은 카드"** 목록이 펼쳐진다(카드 이름·그림, 누르면 카드 상세).
- 데이터: 카드팩 공개 목록 `GET /api/v1/packs`의 세트마다 **`cardIds`(그 세트 카드팩에서 나올 수 있는 카드 id)**를 더한다.
  - 이미 공개된 확률표의 근거가 되는 고정 데이터다. 사용자 데이터는 들어가지 않는다.
  - 캐시는 그대로다(public, s-maxage=3600).
- 못 모은 카드 = cardIds − 내 컬렉션 summary.owned. 계산은 브라우저에서 한다(내 컬렉션은 서버로 다시 보내지 않음).

## 6. 시험
- 단위
  - `rankMovers`: 같은 판본 비교, 7일 전 값 없음은 제외, ₩3,000·5% 문턱, 정렬, 상승·하락 분리, flagged 제외, 오래된 값(14일 넘음) 제외
  - 이름 정확 일치 우선(리자드 → 리자드 먼저, 일레도리자드는 뒤)
  - 덱 비용 합계(장수 곱, 시세 없는 카드 수, 기본 에너지 제외)
  - packs 응답 cardIds 수 = cards
- 실제 DB(dev): 이동 순위 쿼리 결과 형태, 실행 시간
- qa
  - /prices 새 탭(데스크톱·모바일·다크, 화면 밀림, 빈 상태)
  - 진화 링크 결과 순서
  - 덱 비용(편집·공유, 60장 덱, 시세 없는 카드)
  - 수집 현황(퍼센트·완성·못 모은 카드 펼치기)
  - 회귀

## Security 검토 요청 사항
- `/api/prices/top?edition=up|down` 추가(매개변수 규칙·캐시·P-1)와 새 읽기 쿼리의 비용
- 브라우저에서 `/api/prices/batch`를 덱 비용에 쓰는 것(PA-1 메모로 DB 부하가 카드 수에 묶이는지)
- `/api/v1/packs`에 cardIds를 공개하는 것(고정 공개 데이터)
