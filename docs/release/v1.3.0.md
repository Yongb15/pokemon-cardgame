1. `api_rw` 역할 만들기: `node scripts/db-create-role.mjs api_rw <임시파일>` — 운영 owner URL은 neonctl로 받아 변수에만, 비밀번호는 임시 파일 → Secret Manager → 파일 삭제. **0005보다 먼저**(R-4)
2. 마이그레이션 0004~0011: `DATABASE_URL_OWNER="$OWN" npm run db:migrate`. 운영엔 `dev_marker`가 없어 0005의 DO 블록은 아무것도 부여하지 않는 게 정상(R-4)
3. 확인(불리언만): `scripts/db-check-api-role.ts`(운영 api_rw URL) — REQUIRED + DATA 권한 모두 true, 금지 권한 0, `dev_marker` SELECT false, `app_rw`는 account 접근 불가·public 시세 테이블 권한은 그대로
4. 시세 회귀(R-3): 정식 `/api/cards/<id>/prices` 200, `/api/cron/prices` 토큰 없이 401

## 3. 비밀 값 묶음 `api-secrets-prod` v5
- v4 내용 + `DATABASE_URL`(운영 api_rw, pooled, sslmode=require) + `OAUTH_COOKIE_KEY`(새로 생성, 32바이트 base64url) → v5
- `PROXY_SECRET`은 Vercel Production의 `PROXY_SECRET`과 같은 값이어야 함(비교 결과만 확인)
- `\r` 제거(Windows openssl), 출력 금지
- 옛 이미지에 v5를 먼저 넣지 않기: 옛 이미지는 새 키를 몰라 시작을 거부함

## 4. 배포
1. `package.json` 1.3.0 커밋(develop) → **develop → main PR** → CI `check` 통과 → merge commit으로 병합(C-1) → main 병합 커밋에 태그 `v1.3.0`
2. Deploy API 워크플로가 `api`에 main SHA 이미지 배포(이미지만 바뀜). 그 사이 새 이미지는 v2(PROXY만)로 떠서 DB·로그인 없이 fail closed: 로그인·데이터 경로 404/401, `/me`는 `{user:null}`(Security (a): 수용)
3. 워크플로 Health check가 끝나는 즉시 같은 이미지로 설정 갱신: `API_SECRETS=api-secrets-prod:5`, `GOOGLE_CLIENT_ID`, `KAKAO_CLIENT_ID`. `AUTH_TEST_PROVIDER`는 절대 넣지 않음(있으면 시작 거부)
4. 시작 로그: 권한 검사 통과, "grants wider than needed" 없음, 만료 세션 정리 오류 없음
5. Vercel production 배포 확인(정식 주소 번들 해시)
6. 정식 `/api/v1/health` → `proxyVerified: true`(C-2: 없으면 middleware 503, 값이 다르면 401)

**롤백**(R-2): `gcloud run services update-traffic api --to-revisions=<이전 리비전>=100 --region asia-southeast3`. 마이그레이션은 넓히는 것뿐이라 옛 이미지와 호환. 웹은 Vercel에서 이전 production 배포로 promote
