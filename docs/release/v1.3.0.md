# v1.3.0 출시 체크리스트 (M6 로그인·계정 + 시세 30일 평균)

현재 운영 상태(2026-10-09 확인, 읽기만 함)
- Neon `production`: 마이그레이션 0000~0003만 적용. `account` 스키마 없음, `api_rw` 역할 없음, `dev_marker` 없음(정상)
- Cloud Run `api`: 이미지 `0e20b90-manual`(2단계 뼈대), `API_SECRETS=api-secrets-prod:2`, env `APP_ENV=production`, `PUBLIC_ORIGIN=https://pokemon-card-dex-green.vercel.app`
- Secret Manager `api-secrets-prod`: v2(사용 중), v4(= v3 + KAKAO_CLIENT_SECRET, 미사용)

규칙: **권한을 넓히는 마이그레이션은 배포 전, 좁히는 것은 배포 후**(ADR 0003, qa B3-1). 이번에는 전부 넓히는 쪽이라 모두 배포 전에 적용. 비밀 값은 화면·채팅·로그에 출력하지 않음(`$(...)` + stdin).

## 1. 사전 확인 (사용자)
- [ ] Google OAuth 클라이언트의 승인된 리디렉션 URI에 `https://pokemon-card-dex-green.vercel.app/api/v1/auth/google/callback` 있음
- [ ] 카카오 REST API 키(01941a1e…)의 카카오 로그인 리다이렉트 URI에 정식 주소 콜백 있음(2026-10-09 등록 확인)
- [ ] Google OAuth 동의 화면: 테스트 모드면 테스트 사용자만 로그인 가능 → 게시(앱 홈페이지·개인정보처리방침 URL = `/privacy`) 여부 결정
- [ ] 카카오: 비즈 앱 전환 전에는 팀원만 로그인 가능한지 확인, 공개 범위 결정

## 2. 운영 DB (배포 전)
1. `api_rw` 역할 만들기: `node scripts/db-create-role.mjs api_rw <임시파일>` — 운영 owner URL은 neonctl로 받아 변수에만, 비밀번호는 임시 파일에 쓰고 Secret Manager에 넣은 뒤 파일 삭제
2. 마이그레이션 0004~0011 적용: `DATABASE_URL_OWNER="$OWN" npm run db:migrate`
3. 확인: `scripts/db-check-api-role.ts`(운영 api_rw URL) — REQUIRED + DATA 권한 모두 true, 금지 권한 0, `app_rw`는 account 스키마 접근 불가

## 3. 비밀 값 묶음 `api-secrets-prod` v5
- v4 내용 + `DATABASE_URL`(운영 api_rw, pooled, sslmode=require) + `OAUTH_COOKIE_KEY`(새로 생성, 32바이트 base64url) → v5 추가
- `\r` 제거(Windows openssl), 출력 금지

## 4. 배포
1. develop → main `--no-ff` 병합, `package.json` 1.3.0, 태그 `v1.3.0`
2. Deploy API 워크플로가 `api`에 main SHA 이미지 배포(이미지만 바꿈)
3. 같은 이미지로 설정 갱신(새 리비전 1개): `API_SECRETS=api-secrets-prod:5`, `GOOGLE_CLIENT_ID`, `KAKAO_CLIENT_ID` env 추가. `AUTH_TEST_PROVIDER`는 절대 넣지 않음(있으면 시작 거부)
4. 시작 로그: 권한 검사 통과, "grants wider than needed" 없음
5. Vercel production 배포 확인(정식 주소 번들 해시)

## 5. 정리 (배포 확인 뒤)
